# Try LaneOrchestrator on your own work

Choose one small bug or feature in a repository you know. Write down what success
looks like before starting. Use the normal LaneOrchestrator workflow and a small
call budget. Review the final diff and run your repository's relevant checks.

If you share feedback through a GitHub issue or Discussion, these five answers
are useful:

1. What were you trying to finish, and what counted as success?
2. Did setup work on your operating system and Codex host? Include versions.
3. Which models and thinking levels were selected, and was the explanation useful?
4. Did the final change pass your checks? What did you have to correct manually?
5. What usage was reported, what remained unknown, and where did the workflow waste time?

Share a minimal reproduction or a public diff if possible. Remove private source,
credentials, personal paths and account details. Do not upload raw session logs
without inspecting them. A useful failure report matters as much as a success.

Maintainers should record the tested version, task outcome and reproducible issue
separately from subjective feedback. Do not treat a prepared feedback form as
evidence that users have tried the product.
