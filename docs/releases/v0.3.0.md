# LaneOrchestrator v0.3.0

`v0.3.0` contains Astra orchestration, per-task model selection, usage controls and
reviewed profile migration. Release verification requires the protected tag
workflow, exact generated archives and `SHA256SUMS`, attestation and a public
installation check. Source version strings alone do not establish availability.

## Highlights

- Astra inspects task context and selects specialist expertise, model, and thinking for each bounded packet.
- Four control profiles and 172 bundled specialists use per-task model binding instead of fixed profile settings.
- Consequential work requires a fresh independent reviewer, including when Astra implements the change.
- Adaptive routing normalizes compatibility-width text, invisible formatting characters, and common Cyrillic lookalikes while preserving explicit read-only and verified editorial scope.
- Profile and specialist migrations keep exact-state previews, one-time approval-bound plans, drift refusal, safe backups, and reviewed uninstall.
- The host can enforce bounded calls and retries through a temporary usage ledger. Missing token counters remain unknown, and the checker does not claim a provider-side token cap.

## Install after publication

After the release and its evidence are publicly visible:

```sh
codex plugin marketplace add KarthikRamesh9149/laneorchestrator --ref v0.3.0
codex plugin add laneorchestrator@laneorchestrator
```

From the resolved plugin root, run `python3 -m laneorchestrator setup` in an interactive POSIX terminal or WSL session. Review the combined four-profile and 172-specialist preview before confirming. Existing exact legacy profiles use the separate `profiles adopt` flow; receipted v0.2.x profiles use `profiles update`. Open a new Codex task after migration so the host can reload model-neutral profiles.

## Release evidence required

The release commit must have exactly 100 acceptance tests, the full repository validator, benchmark thresholds, deterministic archive verification, clean install and migration journeys, a deep security review, and a fresh independent review. After tag creation, verify every tag-triggered workflow result, download that run's artifacts, publish only those exact files, verify the attestation, and repeat the pinned installation from an unauthenticated context.

Security and usage evidence is bounded. It does not establish permanent security, model entitlement, complete token accounting, successful host reload, or end-to-end implementation quality in every repository.
