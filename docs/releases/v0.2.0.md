# LaneOrchestrator v0.2.0 candidate notes

This candidate describes the intended `v0.2.0` tag and release assets. It is not evidence of public availability, a tag, a GitHub Release, live CI, a completed security scan, or independent review. The required ordering is in [RELEASING.md](../../RELEASING.md).

## Highlights

- Adds auditable routing facts, conservative high-risk signal handling, and required-role fail-closed behavior.
- Adds bounded, no-follow local capability discovery and deterministic ranking of untrusted metadata.
- Adds previewed, token-bound configuration and managed-profile lifecycle operations with adoption, backup, drift refusal, and safe uninstall paths.
- Adds deterministic benchmark, archive, checksum, CI, lifecycle, and security-regression coverage.

## Upgrade and lifecycle

The public install command pins the reviewed source with the protected annotated `v0.2.0` release tag. For an upgrade, review the replacement release, update the marketplace registration to its new protected tag, then reinstall the plugin only when the host requires it. Upgrading or installing the plugin never silently applies profiles.

For managed profiles, use the documented `profiles <action> preview --json` flow before every install, update, adoption, or uninstall, then supply its exact unexpired token and matching `approve:<approval_digest>` value only after review. The [command reference](../commands.md) contains the exercised command forms.

An unmanaged collision or managed-profile drift is an expected refusal, not an overwrite. Uninstall preserves unrelated agent files and configuration. Plugin removal removes plugin registration and cached plugin files; it does not remove managed profiles or configuration.

## Compatibility and evidence

Native Windows supports read-only control-plane commands; use WSL for profile or configuration mutation. See [compatibility](../compatibility.md), [benchmarks](../benchmarks.md), [security model](../security-model.md), and [threat model](../threat-model.md) for boundaries and assumptions.

The CI candidate-distribution job generates non-release benchmark and archive evidence from the committed corpus. Only the protected-tag release workflow can label release assets; it reruns the required validation/security gate and publishes a signed GitHub artifact attestation for the generated `SHA256SUMS` subjects. Verify the attestation and [SHA256SUMS](https://github.com/KarthikRamesh9149/laneorchestrator/releases/download/v0.2.0/SHA256SUMS) together before relying on an archive.

Security checks are layered evidence, not a claim of exhaustive scanning or semantic-risk completeness. Do not use these notes in place of the operational release gates.
